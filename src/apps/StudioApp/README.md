# StudioApp — режим «Студия»

Удалённое событие: два ведущих и «третий ведущий» с экраном транслируют из дома. Выбранные комнаты галактики вместо обычной трансляции видят студию, а модератор может вывести в эфир человека из любой комнаты события (вопрос).

Люди остаются в своих комнатах. Комната работает как обычно, меняются только **трансляция** (4 потока: host1, host2, screen, guest) и **quad**.

Режим работает на текущей инфраструктуре галактики (namespace `galaxy/`, Janus prefix `janus`), а не на автономной инфраструктуре webinar.

## Схема

```
StudioClient ?slot=host1  ─┐
StudioClient ?slot=host2  ─┼─► Studio VideoRoom (студийный gxy) ──rtp_forward──┐
StudioClient ?slot=screen ─┘                                                    │
                                                                                ▼
Гость (VirtualApp, своя gxy-комната) ─────────────rtp_forward──────────► Студийный str (Streaming):
                                                                          host1 | host2 | screen | guest | quad
StudioQuadOut (VM: Chrome + захват) ──────────────────────────────────────────────────────────────────▲
                                                                                │
Комнаты активного события (VirtualMqttClient) ◄────── watch(4 маунтпоинта + quad) ┘

Админка, таб Studio ──► retained MQTT galaxy/studio/<eventId> ──► все клиенты
```

## Событие

Хранится в retained MQTT, у брокера есть persistence. Три топика на событие, чтобы два писателя не затирали поля друг друга:

| Топик | Кто пишет | Содержимое |
|---|---|---|
| `galaxy/studio/<eventId>` | админка | определение события (ниже) |
| `galaxy/studio/<eventId>/layout` | админка и StudioClient `slot=screen` | `{layout, ts}` |
| `galaxy/studio/<eventId>/guest` | админка | `{id, display, room, janus, rfid, ts}` или пусто |

```js
{
  id: "<eventId>",
  name: "Человеческое название",
  date: "2026-12-01",        // только для информации
  rooms: [1051, 1052],       // комнаты-участники
  active: false,             // включается и выключается вручную, может повторяться
  studio: {janus: "gxy1", room: 9999, str: "str1"}, // студийная VideoRoom и str с маунтпоинтами
  mountpoints: {host1, host2, screen, guest, quad},  // id маунтпоинтов на studio.str
  ts: 0                      // время последнего изменения
}
```

Значения по умолчанию для новой формы — `STUDIO_DEFAULTS` в `studio.js` (сейчас заглушки, нужно вписать реальные).

Для бэкенда в `guest` есть всё для `rtp_forward`: `janus` (gxy комнаты гостя), `room`, `rfid` (feed id его публикации).

- Комнаты активного события не меняются.
- Пока активно одно событие, но формат (топик на событие, `eventId` везде) рассчитан на несколько одновременных. Комната может быть только в одном событии, админка это проверяет.
- Удалить событие — отправить пустой retained payload в его топик.
- Клиенты подписаны на `galaxy/studio/#` (`StudioStore` в `studio.js`) и ищут активное событие, в котором есть их комната. В `src/shared/mqtt.js` `watch()` топики `galaxy/studio/...` уходят в событие `MqttStudioEvent`.

## Раскладка

| `layout`       | Что видят зрители                           | Звук экрана |
|----------------|---------------------------------------------|-------------|
| `hosts`        | host1 и host2                               | выключен    |
| `screen_hosts` | экран большой, ведущие маленькими плитками  | включён     |
| `screen`       | только экран на всю область трансляции      | включён     |

- `guest` не равен `null`: гость добавляется плиткой (в раскладке `screen` — маленьким PiP).
- Звук ведущих включён всегда, в том числе в `screen`.
- Клиент держит `watch` на всех 4 маунтпоинтах **всегда**, а раскладка только показывает или скрывает плитки. Так переключение мгновенное, без ожидания keyframe.
- Смена раскладки сопровождается короткой анимацией, чтобы появление экрана «выделялось».

Сценарий: клип заранее открыт и шарится в `slot=screen` (раскладка `hosts`, зрители его не видят и не слышат). Ведущий говорит «а сейчас клип», и модератор одной кнопкой переключает `screen` или `screen_hosts`.

## Компоненты

### StudioClient (`StudioClient.js`, entry `studio`)
URL: `?event=<id>&slot=host1|host2|screen`. Вход через Keycloak (любой пользователь): токен нужен для MQTT, проверки ролей нет.

- Заходит в студийную VideoRoom. Слот кладётся в `display` при join, по нему бэкенд выбирает маунтпоинт для `rtp_forward`.
- `host1`, `host2`: камера и микрофон. Ведущие видят и слышат друг друга и экран в комнате напрямую, а гостя — через маунтпоинт `guest`.
- `screen`: «третий ведущий», им может быть кто угодно (обычно модератор). Публикует только экран со звуком. У него есть превью того, что уходит в слот, и кнопки раскладки с горячими клавишами.
- Авторизации пока нет: кто знает URL, тот может публиковать.

### Админка (`admin/StudioAdmin.js`, entry `sadmin`)
Вход как в основной админке (роли `gxy_admin` / `gxy_root`), два таба:
- **Studio** (`admin/StudioManager.js`) — всё, что ниже;
- **Rooms** — обычный список комнат галактики (`AdminApp/AdminRootMqtt`), в нём смотрим превью человека.

Вопросы — это существующий флаг `question` пользователя (кнопка «вопрос» в VirtualApp). Shidur и sndman в событии не используются, поэтому отдельный флаг не нужен. Список берётся из `/rooms` по комнатам события. «Снять» убирает гостя и снимает у него флаг вопроса (`client-question`).

- События: создать, редактировать, выбрать комнаты (с проверкой на пересечение с другими событиями), активировать и деактивировать.
- Вопросы только из комнат события, превью человека.
- «В эфир» / «снять» гостя. Одновременно в эфире только один гость.
- Раскладка (дублирует кнопки StudioClient, источник состояния один).
- Аварийная кнопка «вернуть всех на обычную трансляцию».

У модератора открыты две вкладки: StudioClient `slot=screen` и админка.

### StudioQuadOut (`quad/StudioQuadOut.js`, entry `squad`)
URL: `?event=<id>`. Работает на отдельной VM с Chrome: экран захватывается и отдаётся в маунтпоинт `quad` события.

Подключается к MQTT как сервис с id `squad-<eventId>` (добавлен в `isServiceID`, пароль сервиса). Брокер должен пускать такой clientId. Пока событие не активно, показывает пустой экран.

- Основа — `QuadOut` / `QuadJanus` / `QuadUsers` из webinar: сетка из 16 групп с ротацией, подключение к нескольким gxy.
- Показываются **все** комнаты события (без фильтра по камерам).
- Два события — две VM с разными `event`.

### VirtualMqttClient.js (зрители)
Студийные потоки смотрятся через отдельную Janus-сессию к `studio.str` (`StudioStream.js`), основной `JanusStream` в это время приостановлен (`JanusStream.suspend()`), включая запуски, которые ещё в процессе. Кнопка трансляции в режиме события включает и выключает студийные потоки.

Если комната пользователя есть в активном событии:

- основная трансляция (`videos`/`audios`) выключается, вместо неё `watch` 4 маунтпоинтов студии с раскладкой по `layout`/`guest`;
- quad: `watch(mountpoints.quad)` вместо жёстко прописанного `102` (параметр в `QuadStream` / `initQuadStream`);
- в шапке индикатор режима события и его название;
- граничные случаи: вход в комнату во время события, переход в другую комнату, старт и окончание события.

**Гость** (`guest.id === user.id`):
- микрофон в комнате включён, он говорит как обычно;
- звук маунтпоинта `guest` у него заглушён, чтобы он не слышал себя с задержкой;
- ведущих он слушает через обычную студийную трансляцию.

**Соседи гостя** (`guest.room === room`): фид гостя в комнате **локально** заглушён, иначе они слышат его дважды. Микрофон самому гостю глушить нельзя, иначе пропадёт и форвард.

Вопрос — обычная кнопка «вопрос» (флаг `question`).

Пока не сделано в клиенте: регулировка громкости студии и PiP (показывает основной эфир). Если в комнате во время события кто-то шарит экран, панель показывает экран, а звук студии продолжает идти.

### Бэкенд
- Студийная VideoRoom на выделенном gxy, комната скрыта из списка комнат.
- Студийный str: маунтпоинты `host1`, `host2`, `screen`, `guest`, `quad` с фиксированными портами (статический пул, динамическое создание через API — потом).
- `rtp_forward`:
  - ведущие и экран: из студийной комнаты по слоту из `display`;
  - гость: его **существующий фид из его gxy-комнаты**, отдельно в студию он не заходит.
  - RTCP-порты для PLI (keyframe по запросу), верхний substream при simulcast, кодек совпадает с маунтпоинтом.
- `admin_key` для всех gxy, где могут оказаться комнаты события.
- Восстановление форвардов после рестарта Janus и после переподключения гостя (новый feed id того же пользователя).

## Не делаем (пока)
- Запись.
- Переводы (ждём ответа).
- Shidur и sndman: событие полностью удалённое.
- Авторизацию ведущих.
- Живой диалог с гостем без задержки: задержка ~1–2 с допустима, в основном это вопрос и ответ. При необходимости гостя можно подключить к студийной комнате вторым publisher-хэндлом, как в screen share.
- Динамические маунтпоинты и несколько одновременных событий (формат готов, реализация потом).

## Ветки
- Ветка `studio` создана от `webinar`. Код Studio лежит в новых файлах в `src/apps/StudioApp`, чтобы не конфликтовать.
- Из существующих файлов меняется только `VirtualMqttClient.js` (плюс небольшие обратно совместимые правки: `QuadStream` принимает `stream`, `streaming-utils.js` — `suspend()`, `mqtt.js` — маршрут `galaxy/studio`, `enums.js` — `squad-*`, `App.js` / `package.json` — entries).
- Компоненты quad (`QuadJanus`, `QuadUsers`, стили) скопированы из `WebinarApp` в `quad/`.
